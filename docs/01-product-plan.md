# Product plan

## Vision

AI Dashboard is a self-hosted AI development operations console: projects, repositories, tasks, agents, source control, CI, deployments, models, usage, evidence, optional ideas and automation in one control surface.

The primary use case is connecting an existing project/repository and operating it from one control plane. A user can create tasks directly, delegate work manually, react to GitHub/CI events, or optionally capture a rough Idea and let an AI planner turn it into a bounded task graph.

The long-term goal is optional end-to-end autonomy without giving one model unchecked authority over the whole lifecycle.

## Core product model

**Project is the root object.** Ideas are optional children of a Project, not the mandatory beginning of a workflow.

```text
Project / existing repository
  |
  +-> Task created manually -----------+
  +-> direct agent instruction --------+--> Worker run(s)
  +-> GitHub issue / CI event (M2) ----+        |
  +-> optional Idea -> AI Planner -----+        v
                                           checkpoint/evidence
                                                |
                                                v
                                      independent Supervisor
                                         /        |        \
                                    approve    changes    blocked
                                       |          |          |
                                       v          +----> retry/human
                                  merge/cleanup
                                       |
                                       v
                                      done
```

Every transition remains visible and persisted. Human control is always available, even when a project runs in autonomous mode.

## Entry points

### Existing project/repository

This is the default path. Register an existing local codebase, optionally bind its GitHub repository, then create/delegate tasks immediately.

The bootstrap currently supports one primary local `repoPath` per Project. First-class multi-repository projects are a future extension.

### Direct tasks

Tasks can be authored by the user, imported from integrations, or generated by an AI planner. They all enter the same task/run/evidence pipeline.

### Ideas — optional

Ideas are a brainstorming and incubation feature inside an existing Project. An Idea can start as rough notes, be sent to a planner agent, become a dependency-aware task graph and then disappear into the normal task pipeline.

Ideas are never required to use agents, autonomy, review or merge.

### Integration-driven work

GitHub issues, CI failures, schedules and other events can create or resume tasks directly. They do not need to be converted into Ideas first.

## Project autonomy modes

### Manual

The control plane records state but only starts workers, reviews and merges when explicitly requested. Idea planning, when used, is also manually triggered.

### Assisted

AI planning and supervisor review are available while execution/merge remain user-triggered.

### Autonomous

The control loop may automatically:

- analyze queued Ideas when `autoAnalyzeIdeas` is enabled
- start ready tasks regardless of whether they came from a user, planner or integration
- reconcile OpenCode runs and enforce timeout/retry budgets
- launch an independent supervisor after successful worker completion
- send rejected work back for another bounded iteration
- merge supervisor-approved work when `autoMerge` is enabled
- remove completed worktrees/branches after merge

Autonomy is opt-in per Project and is bounded by explicit limits.

## Product areas

### Projects

Each Project represents a working product/codebase context and links its repository/workspace, roadmap state, active work, blockers, PR/CI state, deployments, agent activity and autonomy policy.

### Tasks

Tasks have priority, dependencies, acceptance criteria, assigned agent role, runner/model policy and evidence requirements. Tasks retain iteration and supervisor feedback so rejected work can loop without losing history.

### Ideas

Ideas are optional durable notes attached to a Project. Their only special power is that a planner can turn them into normal Tasks.

### Agents and runs

An agent is a configured capability/role. A run is one execution attempt. Runs record kind (`planner`, `worker`, `supervisor`), status, runner, workspace, branch, timestamps, result contract, checkpoint and evidence.

### Supervisor

The supervisor is independent from the worker role. It verifies the resulting checkpoint rather than trusting worker claims. The supervisor produces a machine-readable verdict but does not execute the final merge itself. The control plane performs merge/cleanup only after integrity gates pass.

### Git and GitHub

Each delegated coding task receives an isolated worktree/branch. Successful worker output is checkpoint-committed before supervisor review. The bootstrap can safely fast-forward an approved branch into a clean local base branch. GitHub PR/check/review synchronization is the next integration layer.

### Integrations

OpenCode is P0/M1. ACP becomes the preferred generic protocol where practical. Codex, Claude Code, local agents and other harnesses remain adapters.

### Automations

Automation can create/resume Tasks from schedules, CI failures, GitHub events or other integration events. It must use the same Project/Task/Run/Evidence model rather than bypassing it. Ideas remain optional and are used only when brainstorming/planning semantics are useful.

## Machine-readable agent handoff

Planner, worker and supervisor prompts end with an `AI_DASHBOARD_RESULT` JSON contract. The control plane parses this result instead of guessing completion from prose, but applies it only after the owned OpenCode session is proven `idle` or missing. `busy`, retrying and unknown status retain Run/scope ownership; timeout or abort does not release that ownership until explicit stop evidence exists.

Later versions should replace or supplement text parsing with an MCP/ACP-native result submission tool.

## Non-goals for bootstrap

- multi-user RBAC
- public SaaS hosting
- arbitrary remote shell exposure
- building our own LLM inference stack
- replacing GitHub as source-control hosting
- forcing every piece of work through Idea/planning
- allowing an agent to self-approve and directly merge its own unverified work
